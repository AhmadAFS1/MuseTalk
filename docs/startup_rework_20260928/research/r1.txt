summary:
  1) The "required recipe" (plan L78; chin_fps README L3) has five parts: TAESD decoder, MuseTalk's native avatar encoder (SD-VAE latents prepared ahead, no runtime cost, no flag), 100% chin alignment, refined seam, and expressive H3 sources. Only the decoder can be switched on at startup today: MUSETALK_VAE_BACKEND=taesd (scripts/vae_fast_decoder.py:16,81). Chin and seam are OFFLINE ONLY. There is no FaceMesh or chin code in api_server.py, hls_gpu_scheduler.py or api_avatar.py (checked by grep; the only related flags are the unrelated MUSETALK_SIDE_JAW_BLEND and source-mouth blend). Every MUSETALK_CHIN_* flag in the plan (3.0a-3.7) is proposed and does not exist.
2) The startup chain boots the OLD recipe, confirmed on the live process. pid 3555159 was started by run_trt_stagewise_server.sh --profile throughput_record and has MUSETALK_VAE_BACKEND=trt_stagewise. That is the int8 SD-VAE decoder, 82.9 ms per bs8 batch, against TAESD at 6.3-6.8 ms: offline pipelined 73.9 fps vs 250.8 fps. The user's TAESD launcher (experiments/chinese_bob_webrtc_20260927/run_local_api.sh) works around this: it sources the sm89 env, then exports MUSETALK_VAE_BACKEND=taesd and execs api_server.py directly, skipping every start script.
3) What is proven on the GPU:
- Plan (short bursts): shipping TRT UNet bs8 23.43-24.6 ms per bs8 (2.93-3.08 ms/frame); compiled TAESD 0.74-0.85 ms/frame; TRT TAESD full height 0.486 ms/frame; GPU path 30.93 ms per bs8 = 258.7 fps.
- New 2026-09-28 run of 200 s sustained (docs/fps_comparisons/4070s_300fps_impl_20260928/foundation/foundation_results.json): 260.08 fps. Per bs8: UNet 24.22 ms, TAESD 6.35, H2D 0.03, post+D2H 0.13. Power-bound at 211.6 of 220 W, SM clock 2580 MHz. Turning the syncs off gave 258.1 fps, so no GPU gain on its own.
4) "160 fps" is the offline one-stream harness: refined-seam chin 163.4 / 168.8 fps, rendered at 24 fps, excluding TTS, scheduling, WebRTC and encode. Other offline numbers: chin100 v1 182.8-197.7, pipelined standard 250.8, serial TAESD 204-219.6.
- Live has never been measured cleanly beyond 3 peers. The contaminated 10-stream wall run delivered 136-145 fresh fps (TAESD, no chin, libx264 medium).
- The structural single-process live ceiling is 174-203 fps: 3 syncs plus a blocking D2H per batch, the handoff blocking the scheduler for 8-10 ms per batch, and idle-mp4 decode on the event loop capping at about 183 fps.
5) Nearly every Phase 1 serving fix is CODE, not configuration. None of these flags exist: HLS_GPU_PIPELINE_DEPTH, WEBRTC_NONBLOCKING_HANDOFF, WEBRTC_YUV_CONVERTER, WEBRTC_IDLE_FRAME_CACHE, HLS_SCHEDULER_POLICY, HLS_SKIP_GPU_FOR_RAW, MUSETALK_THREAD_CAPS, HLS_GPU_BLOCKING_WAIT, WEBRTC_NATIVE_VP8_THREADS, WEBRTC_H264_IMPL.
