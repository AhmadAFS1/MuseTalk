# Private character preparation runtime

The reused diagnostic base retains compiled MMCV; its installation-only `openmim` CLI is removed because its download dependencies were already pruned. All three resulting runtime environments must pass `pip check`. Historical media/showcases are excluded from the image build context. The image contains two separate pinned Linux environments (H3 CUDA13 and MuseTalk preparation CUDA12.1), ComfyUI, MediaPipe QC and only the VAE/face-parser/DWPose/S3FD preparation weights. It contains no MuseTalk teacher UNet, Whisper weights, TensorRT renderer engines or Core ML training path. The phone retains the approved shared student checkpoint `a05d2d98…`, source24/render25.

`character_factory/character_worker/install_character_worker.sh --build-runtime` completes the image paths/helpers without fetching secrets, downloading H3 model weights or claiming CUDA qualification. H3's `--environment-only --profile character-fl2va` prebuilds the locked environment. CPU verification writes `/opt/character-runtime/manifest.json`; its SHA and the registry image digest are separate deployment pins.

Production sets `CHARACTER_WORKER_RUNTIME_MODE=prebuilt`, `REPO_ROOT` and `CHARACTER_WORKER_REPO` to `/opt/character-runtime/app`, and the expected `CHARACTER_WORKER_RUNTIME_MANIFEST_SHA256`. The template executes the baked `vast_onstart_character.sh`; do not clone another checkout or mount a volume over baked `/workspace`. Startup rejects source, package, helper, ComfyUI, lock or preparation-weight drift. It then bootstraps runtime credentials and downloads/verifies only missing `character-fl2va` weights (40,073,842,159 bytes; Qwen, FL2VA and both VAEs). The full H3 profile remains available independently. No dependency repair or `pip install` runs at production boot. Source installation remains an explicit development/repair mode using a separately reviewed runtime.

The `Private character preparation runtime candidate` workflow builds only after a source-SHA request on `codex/character-device-release`. Its task-specific Actions secret holds checksum-pinned, expiring S3 input URLs; downloads occur outside Docker and URL values are masked. H3 is supplied as a pinned git bundle, without GitHub credentials. The image is published only to the existing private GHCR package and a unique tag. Registry credentials are per-rental `image_login`, never container environment variables. Candidate receipts explicitly state GPU qualification has not run. A fresh exact RTX3090 single-job qualification, source/render distinction, all mandatory S3 artifacts and cleanup are required before changing production pins.

Use the Vast **docker ENTRYPOINT** template mode (`runtype=args`, no arguments or on-start override). Vast's SSH startup can change Ubuntu packages before the worker verifies its immutable manifest. The controller must supply the exact `MUSETALK_REF`, `CHARACTER_WORKER_RUNTIME_MANIFEST_SHA256`, `CHARACTER_WORKER_IMAGE_DIGEST` and per-rental TLS credentials. The baked PID 1 runs the existing worker startup, supervises the worker API, and shuts down H3 process groups when the container exits. Optional `CHARACTER_WORKER_ENABLE_SSH=1` requires a public key and starts the already-installed OpenSSH with per-container host keys. Production can leave SSH disabled.

Release `lingua-character-release/2` requires `qc.contract=lingua-preprocessing-qc/1`. Its passed report measures source/endpoint QC, cache/archive completeness, finite FP16 latent geometry and every JPEG/PNG decode. It records `phone_student_acceptance=not_run_on_linux`. Teacher smoke is an optional labeled diagnostic and never a substitute for actual student execution. Historical `/1` releases remain immutable and are read separately by the backend. The release JSON uploads last.

Protected control uses `CHARACTER_WORKER_REQUIRE_TLS=1` plus a per-rental bearer and base64 PEM certificate/key provisioned by the backend over the provider HTTPS API. Port8010 serves TLS only; the backend validates certificate, server name and SHA256 pin. The worker removes the private-key file after loading, strips the key from child environments, and verifies local HTTPS with the public certificate. No TLS material is baked into the image. Missing/invalid TLS fails boot; legacy local tests explicitly omit TLS.
